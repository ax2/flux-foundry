# Stage-10 首屏与无进展球路设计

## 资源与首帧
保留原始PNG到art/source，Pillow/WebP quality90/method6，场地保持941×1672，图集按等比例降为1536×512，透明轮廓与归一化裁切坐标不变。生成src/assets/*.webp和asset-manifest.ts，Vite按内容哈希命名，旧PNG不进入发行目录及SW预缓存。

RAF在模块就绪后立即启动。未加载图片时Canvas程序绘制材质底板、原三角仓、全部弹珠和积木，布局/碰撞/数字与正式贴图一致；加载失败也能玩。HTTP流按接收字节/已知资源体积更新，解码前最多99%，两张真正解码后100%并收起。失败显示简化材质和重试，仅重新加载失败项。Windows file:不使用fetch，直接图片解码，按实际完成文件报告字节。HTTP单项30秒中止只转备用材质，不影响游戏或删除弹珠。CSP只为图片解码补充blob:，其余保持自源。

## 观察诊断
Game.progress只统计模拟时间：当前/最长连续无有效命中、连续接球未命中次数；有效扣1即重置当前项，暂停不增长。只读fluxDiagnostics包含独立墙钟、帧数、最后一帧、最大帧间隔、页面可见性、加载状态。UI工具每约1秒保存场景；300秒观察上限分类为后台、暂停、帧停滞、真实无进展、模拟变慢或有效长飞行，保存快照与截图，不修改游戏状态。后台通过正常前台/继续菜单恢复，不加速、不收球。

## 无进展辅助
旧精确位置/速度重复检测保留。另在至少8模拟秒无命中且连续救球4次后，挡板准备可见蓄能，并在球落到470以下、距表面仍至少28逻辑像素时选择机械面。最多每80ms一次，只读估算17种±0.32以内倾角，估算共用重力、羽化风场、被动墙反射、闸门/柱子、积木几何和运动时间；只实际接触才反射，不能中途修改球。

下一次驱动的供能在22000/28000/40000间变化，正常18000，沿向上的机械驱动做功并受240000上限约束；金色机械面/灯光与碰撞火花标识充能。有效命中即复位，漏球清除临时机械姿态。没有接球额度、球寿命、强制漏球或主动按钮。此类兼容修复不改变关卡数字、目标、三星条件或清空当前星级。
