# Stage-21 可见更新、整局保护与多页保存

2026-11-08。起点为Stage20已重现的PWA旧受控页刷新仍旧版、无更新提示。目标是玩家能知道版本和安全切换时机，同时保留当前局及成绩；不修改球、关卡、原PNG或存档规则版本。

## 更新交互

设置显示15px版本、14px状态和至少44px按钮，顶栏只加提示点。首次发射前或整局won/over才允许主动更新。已花一颗但phase仍aim属于同一局，不能刷新；飞行中同样保护。成绩写入失败显示重试，保存期间不能关闭菜单切回对局。等待更新不阻断继续游戏。键盘Tab/ShiftTab在动态按钮替换/禁用后仍留在菜单。

AppUpdates单独处理注册/检查/等待/应用状态。原图解码完延后注册，自动检查分钟节流，离线不请求。设置手动检查可强制触发；发现待更新版本后不重复下载。构建版本统一从package.json注入。

新worker不在install时强制接管。只有玩家点击更新且保存成功、安全条件再次成立后发送FLUX_ACTIVATE，收到controllerchange再刷新发起页；其他页只提示、不自动刷新。保存准备和激活请求分离，避免另页接管时刷新仍在等待保存的页。首次active仍activating时等待生命周期完成再update。激活10秒观察超限恢复重试状态，**不是弹珠寿命**。保存时waiting消失也恢复可操作状态。

显式激活对应[skipWaiting](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/skipWaiting)；更新脚本检查使用[updateViaCache:none](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/updateViaCache)，该选项不等于重新下载图片。

## 原图与缓存

SW生成时排序文件、稳定hash。首次离线安装在浏览器已下载原图之后，hash资源使用HTTP缓存；升级优先从CacheStorage逐字节复制相同hash资源，shell使用reload。未压缩/缩图/转WebP。导航只用当前worker自己的shell，保留上一代资源，避免另一个旧页立即丢失依赖。

仅验证当前与上一代共存；没有证明三代以上长期驻留页、任意连续回滚或浏览器自行清理存储后的所有组合。不能声称长期离线永久可用。

## 稳定存档

保持flux-save/schema1/paddle-natural-1及v3–v8历史。每次保存前读取最新内容、合并最佳星级/最少耗珠与其他规则集，避免旧页设置写回覆盖新成绩。新排行加本地ID，区分两个分数相同的真实对局；旧无ID条目使用多重集合并，保留旧重复次数但不重复共享快照。

网页版通过[Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)按flux-save串行化读合并写。Windows file或无API时保留同步合并，未声称该回退拥有跨进程事务性。只有实际修改的声音/特效/选珠偏好写入，防止旧页修改声音时覆盖另一页的特效。操作系统默认简化不被当作用户显式偏好写入。更新等待真实保存完成并核对写回内容。

## 验证区分与旧版迁移

原生Chrome专项使用两份真实编译0.20.0与本地0.20.0-next-test，同origin动态切换；1.5秒首次激活延迟、503、下载门控、保存异常/锁均明确为测试夹具。第一关一发三星来自实际UI合法输入，不注入球/得分。另一页自然回收后仍未结束整局，更新禁用；第三页自主升级且旧局留在内存。另有waiting消失的生命周期单测，不冒充原生浏览器覆盖。

从v0.19.0真实Windows包提取旧dist的独立迁移探针显示：旧页首次升级仍须完成局后关闭所有游戏页签/窗口一次，新v0.20之后才拥有可见更新流程。进度/历史/选珠/声音使用显式存档夹具验证迁移，不是赚取星级的路线。旧代码无法被本版追溯改写，不强制导航旧局来掩盖该限制。

正式物理只做只读验证，52套自然三星不重生成；七矩阵6336行与Stage20结果精确一致。Stage22收紧的两例回归一同进入本版。实体手机、安装态PWA、WebKit、低端FPS与人耳听感未完成，Chrome仿真不能代替。
